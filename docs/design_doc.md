# 設計ドキュメント - TSD-107 ずんだ読み上げ (FCIS+SMAC対応)

## 📖 このドキュメントについて
- アプリの要件・概要を記載する設計ドキュメント
- ボトムアップフィードバックで実装から抽出した**S/A評価の「車輪の発明」**を蓄積する

### ボトムアップフィードバックの原則
1. **スクラップ&ビルド**: shell, coreなど層ごとに実装を何度も作り直す（FCIS+SMACの破壊の安全性）
2. **評価と抽出**: ユーザーが納得し指示を出したら実装からS/A評価の設計判断を抽出
3. **ドキュメント更新**: 抽出した「発明」をこのドキュメントに追記
4. **齟齬修正**: 実装とドキュメントの食い違いは実装側に合わせる（実装が正）

### 評価基準
- **S評価（必須追記）**: 設計判断の分岐点、WHYを含む、普遍的な知見
- **A評価（推奨追記）**: プロジェクト固有だが重要な設計判断
- **B/C評価（追記不要）**: 実装から自明、型定義、UI詳細、一般的な技術選定

### Attention分散防止
各担当AI（Shell/State/Core）は以下のみ読む:
- **全体設計（必読）**: アプリの要件・概要。全層が知るべき契約と方針
- **自分の層のセクション**: その層のS/A評価発明
- 他層のセクションの存在は忘れて構わない

## **1. 全体設計（全担当者共通）**

**【全担当AI必読】このセクションは全ての層の実装者が参照します。**

### 1.1 プロジェクト概要

**ずんだ読み上げ (TSD-107)**

VOICEVOXエンジンを使用したテキスト読み上げWebアプリケーション。
ずんだもん・四国めたんのキャラクター音声でテキストを読み上げ、MP3でダウンロード可能。
OCR機能で画像からのテキスト抽出にも対応。

### 1.2 技術スタック

| カテゴリ | 技術 | バージョン |
|---------|------|-----------|
| Framework | Next.js (App Router) | 14.2.5 |
| Language | TypeScript | 5.5.4 |
| Styling | Tailwind CSS | 3.4.6 |
| State Management | XState | 5.x |
| OCR | Tesseract.js | 5.1.1 |
| 音声エンジン | VOICEVOX | Docker |
| 音声変換 | fluent-ffmpeg | 2.1.3 |

### 1.3 アーキテクチャ原則

- **FCIS+SMAC**: Pure Functions (Core) + State Machines (State) + Thin Shell
- **層分離**: Core/State/Shell の責務を厳密に分離
- **契約駆動**: 層間は types.ts の契約のみで連携
- **スクラップ&ビルド**: 実装は何度も作り直す。知見のみドキュメントに蓄積

### 1.4 主要機能

| 機能 | 説明 |
|------|------|
| 話者選択 | ずんだもん(ID:3)、四国めたん(ID:2)をラジオボタンで選択 |
| テキスト入力 | 最大50,000文字、リアルタイム文字数カウント |
| OCR入力 | JPEG/PNG/WEBP対応、最大5MB、ドラッグ&ドロップ |
| 音声生成 | 500文字チャンク分割、ストリーミング進捗表示、WAV結合 |
| ダウンロード | `{話者名}_{タイムスタンプ}.wav` 形式 |

### 1.5 API仕様

**POST `/api/voicevox/generate`**
```typescript
// Request
{ text: string; speaker: 2 | 3 }

// Response (NDJSON Streaming)
{"type":"progress","current":1,"total":100}
{"type":"progress","current":2,"total":100}
...
{"type":"complete","audio":"base64encodedWAV"}
```

### 1.6 制約事項

| 項目 | 制約 |
|------|------|
| 話者 | 2体のみ（ずんだもん、四国めたん） |
| スタイル | ノーマル音声のみ |
| 言語 | 日本語のみ |
| 出力形式 | MP3のみ |
| 再生機能 | なし（ダウンロードのみ） |
| 環境 | Docker必須（VOICEVOX依存） |

## **2. Core層設計**

### 2.1 責務
純粋関数によるビジネスロジック。副作用なし、テスト100%可能。

### 2.2 必要な関数

| 関数 | 入力 | 出力 | 説明 |
|------|------|------|------|
| validateText | text: string | Result<void, ValidationError> | テキストバリデーション（空文字、文字数制限） |
| splitIntoChunks | text: string, size: number | string[] | テキストをチャンク分割（デフォルト500文字） |
| normalizeOcrText | text: string | string | OCRテキスト正規化（スペース除去等） |
| getSpeakerConfig | speakerId: SpeakerId | SpeakerConfig | 話者設定取得 |
| generateFilename | speakerId: SpeakerId | string | ファイル名生成 |

### 2.3 OCRテキスト正規化ルール
- 日本語文字間の不要スペース除去
- 括弧内スペース正規化
- 句読点前後スペース除去
- 数字間・数字と日本語間スペース除去
- 連続スペースを単一スペースに統一

### 2.4 S/A評価の発明（ボトムアップフィードバック保管庫）

- **S評価: OCRテキスト正規化の収束ループ**
  - WHY: 正規表現1回では「あ い う」のような連続パターンを完全処理できない
  - 収束するまで繰り返し適用で任意長の不要スペースを除去
  - 実装: `while (prev !== result) { prev = result; result = result.replace(...); }`
  - 普遍的知見: 正規表現の限界を繰り返し適用で補うパターン

## **3. State層設計**

### 3.1 責務
状態管理とAPI通信。XState v5の状態機械を使用。

### 3.2 状態定義

```typescript
interface AppState {
  // 入力状態
  text: string;
  speakerId: 2 | 3;
  inputMode: 'text' | 'ocr';
  
  // OCR状態
  ocrImage: File | null;
  ocrProgress: OcrProgress | null;
  
  // 音声生成状態
  status: 'idle' | 'generating' | 'success' | 'error';
  generateProgress: { current: number; total: number } | null;
  audioBlob: Blob | null;
  error: string | null;
}
```

### 3.3 イベント

| イベント | 説明 |
|---------|------|
| SET_TEXT | テキスト更新 |
| SET_SPEAKER | 話者変更（音声・エラーリセット含む） |
| SET_INPUT_MODE | 入力モード切替 |
| START_OCR | OCR処理開始 |
| GENERATE | 音声生成開始 |
| RESET | 状態リセット |

### 3.4 タイムアウト設定
- チャンクごとタイムアウトリセット方式: 1チャンク60秒
- ストリーミングAPIで進捗を受信し、受信ごとにタイムアウトをリセット

### 3.5 S/A評価の発明（ボトムアップフィードバック保管庫）

- **S評価: fromCallbackによる進捗イベント送信**
  - WHY: fromPromiseでは中間状態を返せないが、長時間処理では進捗表示が必要
  - `sendBack({ type: 'GENERATE_PROGRESS', ... })`で任意タイミングでイベント送信
  - 普遍的知見: 長時間非同期処理のUX向上パターン

- **A評価: チャンクごとタイムアウトリセット**
  - WHY: 50,000文字（100チャンク）の一括タイムアウトは非現実的
  - 各チャンク完了ごとにタイムアウトをリセットし、無限待機を防止
  - 実装: ReadableStreamで進捗JSON受信 → resetTimeout()呼び出し

## **4. Shell層設計**

### 4.1 責務
UIとIO処理。可能な限り薄く、ロジックを持たない。

### 4.2 画面構成

```
┌─────────────────────────────┐
│  VOICEVOX音声生成システム    │
│  好きなキャラクターの声で    │
│  読み上げます！              │
└─────────────────────────────┘
│
├─ 話者選択 (ラジオボタン)
│  ├─ ずんだもん ○
│  └─ 四国めたん ○
│
├─ 入力モードタブ
│  ├─ [テキスト入力]
│  └─ [画像からOCR]
│
├─ 入力エリア（モードに応じて切替）
│  ├─ テキストエリア + 文字数カウント
│  └─ ドラッグ&ドロップ + プレビュー
│
├─ 生成ボタン（話者依存テキスト）
│  ├─ 「ずんだもんの声で読み上げるのだ！」
│  └─ 「四国めたんの声で読み上げてね！」
│
├─ ローディング表示
│  └─ プログレススピナー
│
└─ 完成時
   ├─ ダウンロードボタン
   └─ もう一度作るボタン
```

### 4.3 動的テキスト

| 要素 | ずんだもん | 四国めたん |
|------|-----------|-----------|
| プレースホルダー | `ここにテキストを入力するのだ！` | `ここにテキストを入力してね！` |
| 生成ボタン | `ずんだもんの声で読み上げるのだ！` | `四国めたんの声で読み上げてね！` |

### 4.4 カラーテーマ
- メインカラー: ずんだもん緑 (`zundamon-green`, `zundamon-dark`, `zundamon-light`)

### 4.5 S/A評価の発明（ボトムアップフィードバック保管庫）

- **A評価: 自動高さ調整テキストエリア（上限付き）**
  - WHY: 入力量に応じた動的調整でUX向上、400px上限で無限伸長防止
  - 実装: `Math.min(textarea.scrollHeight, 400)px`

- **A評価: ドラッグ&ドロップとクリックの統合UI**
  - WHY: どちらでも同じ結果が得られる直感的なファイル選択
  - 実装: onDrop + onClick で両方の入力経路を同一コンポーネントで処理

- **A評価: OcrUploadのメモリリーク防止**
  - WHY: URL.createObjectURLで作成したURLはrevokeObjectURLで解放必須
  - 実装: useEffect + cleanupでライフサイクル管理
