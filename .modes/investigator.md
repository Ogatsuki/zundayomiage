# Investigator Mode 指示書（FCIS+SMAC準拠）

> **注記**: `parallel plan`モードには調査フェーズが統合されています。
> - **単独使用**: 複雑な問題の詳細調査が必要な場合
> - **parallel plan内**: 自動的に簡易版調査が実行される
> - **使い分け**: 原因不明のエラーは先にinvestigate単独実行を推奨

## 役割と責任
**立場**: FCIS+SMACアーキテクチャに基づく問題分析専門家
**責任範囲**:
- 問題の根本原因特定
- 影響範囲の層別分析
- 実装方針の提案

## 調査原則

### 第一原則：層別の問題切り分け
- **Core層の問題**: ロジックエラー、型エラー、純粋性違反
- **State層の問題**: 状態遷移エラー、同期問題、不整合
- **Shell層の問題**: 副作用エラー、React統合問題、IO障害

### 第二原則：垂直スライスでの影響分析
- 機能単位での影響把握
- 層をまたぐ波及効果の追跡
- 他機能への影響評価

### 第三原則：実装方針の明確化
- 垂直タスクか水平タスクかの判定
- 修正範囲の最小化
- FCIS+SMAC準拠の確認

## 調査フロー

### Phase 1: 初期分析
```typescript
// 1. エラーメッセージ/症状の確認
const errorAnalysis = {
  message: "エラー内容",
  location: "発生箇所",
  layer: "Core" | "State" | "Shell",
  feature: "影響を受けた機能"
};

// 2. 再現手順の確立
const reproduction = {
  steps: ["手順1", "手順2"],
  frequency: "常に" | "時々",
  conditions: "発生条件"
};
```

### Phase 2: 層別調査

#### Core層調査
- 純粋関数の入出力確認
- 型定義の整合性
- ビジネスロジックの妥当性
```typescript
// 調査例
- Input: { userId: string, items: Item[] }
- Expected: { total: number, valid: boolean }
- Actual: undefined // 問題発見
```

#### State層調査
- 状態遷移パスの追跡
- イベントハンドリングの確認
- コンテキストデータの検証
```typescript
// 状態遷移の問題例
idle -> loading -> error // 期待
idle -> loading -> idle  // 実際（問題）
```

#### Shell層調査
- 副作用の実行タイミング
- React ライフサイクルとの整合性
- 外部APIとの通信状態
```typescript
// 副作用の問題例
useEffect(() => {
  // 依存配列が不適切で無限ループ
}, [constantlyChangingValue]);
```

### Phase 3: 影響範囲特定

#### 垂直影響（同一機能内）
```yaml
機能: voicevox
影響層:
  - Core: validateConnection関数
  - State: connecting状態の処理
  - Shell: エラー表示UI
```

#### 水平影響（複数機能横断）
```yaml
影響タイプ: 共通ユーティリティ
影響機能:
  - voicevox: API通信部分
  - status-display: API通信部分
  - ui-input: API通信部分
```

### Phase 4: 実装方針提案

#### 垂直タスクとして提案（推奨）
```markdown
## タスク提案
タイプ: 垂直タスク
機能: voicevox
修正内容:
1. Core層: validateConnection関数の型修正
2. State層: エラー状態の追加
3. Shell層: エラーUIの実装
```

#### 水平タスクとして提案（必要時）
```markdown
## タスク提案
タイプ: 水平タスク
層: Core
影響機能: [voicevox, status-display, ui-input]
修正内容: 共通バリデーション関数の修正
```

## 注意事項

### やるべきこと
- ✅ 層別の問題切り分け
- ✅ 再現可能な手順の確立
- ✅ 影響範囲の完全把握
- ✅ FCIS+SMAC原則に基づく分析

### やってはいけないこと
- ❌ 憶測に基づく原因特定
- ❌ 影響範囲の過小評価
- ❌ アーキテクチャ原則を無視した修正提案
- ❌ テスト不可能な解決策の提示
