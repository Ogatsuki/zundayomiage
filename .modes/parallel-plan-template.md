# Parallel Plan Template - ハイブリッド方式

このテンプレートは`parallel plan`モード実行時に使用される、調査統合型の並列実行計画テンプレートです。

## 実行フロー（セッション1で実行）

### フェーズ1: 自動調査（Investigator統合）
```
1. 問題の根本原因分析
   - エラーメッセージと症状の詳細確認
   - 再現手順の特定
   - 影響範囲のマッピング

2. FCIS+SMAC層別分析
   - Core層: ビジネスロジックの問題点
   - State層: 状態管理・遷移の問題点
   - Shell層: 副作用・React統合の問題点

3. 依存関係の把握
   - モジュール間の依存関係
   - 外部ライブラリとの統合点
   - 既存コードの制約事項
```

### フェーズ2: 全体設計
```
1. アーキテクチャ設計
   - 解決アプローチの決定
   - FCIS+SMAC準拠の設計パターン選択
   - パフォーマンス・保守性の考慮

2. 契約定義
   - 共通インターフェース設計
   - TypeScript型定義
   - タスク間の入出力契約

3. 制約事項の明確化
   - ファイル編集の排他制御
   - 命名規則とコーディング規約
   - 競合防止ルール
```

### フェーズ3: タスク分割と指示書生成

#### タスク分割戦略
- **垂直分割優先**: 機能単位で独立したタスク
- **水平分割許可**: 必要時のみレイヤー別タスク

#### 指示書生成
各セッション用の独立した完結指示書を生成：
- `./parallel-sessions/session-a.md`
- `./parallel-sessions/session-b.md`
- `./parallel-sessions/session-c.md`

- 問題: 型の不一致
- 解決: 契約仕様の型定義を再確認

**ビルドエラー**
- 問題: import/export エラー

- 問題: 二重レンダリング
- 解決: useEffectOnceパターン使用

**状態管理の不整合**
- 問題: 予期しない状態遷移
- 解決: State層の状態遷移図確認

## 重要原則

1. **完結性**: 各指示書は他を参照せず単独で実行可能
2. **具体性**: 曖昧さを排除し、具体的な行動を指示
3. **検証可能性**: 明確な完了基準で成功を判定
4. **競合防止**: ファイル編集の重複を完全排除
5. **自律性**: 詳細実装は各セッションの創造性に委ねる
