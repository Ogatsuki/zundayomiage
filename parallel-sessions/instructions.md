# 並列実行指示書 - スタイル修正タスク

## 概要
**問題**: アプリケーションにスタイルが全く適用されていない
**原因**: Tailwind CSSは設定されているが、コンポーネントにスタイルクラスが存在しない
**アーキテクチャ**: FCIS+SMAC準拠

## 並列タスク分割（垂直分割優先）

### セッション1: スタイル基盤タスク
**責任範囲**: Tailwind設定とグローバルスタイル
**作業内容**:
1. `tailwind.config.ts`の設定確認と修正
2. `globals.css`の拡張（必要なカスタムスタイルの追加）
3. カラースキーム定義（ずんだもんテーマ：緑基調）
4. フォント設定の適用

**影響ファイル**:
- `tailwind.config.ts`
- `app/globals.css`
- `app/layout.tsx`

---

### セッション2: コンポーネントスタイルタスク
**責任範囲**: 各UIコンポーネントへのTailwindクラス適用
**作業内容**:
1. メインページコンポーネントへのスタイル適用
2. 音声合成コントロール部分のスタイリング
3. テキスト入力エリアのスタイル設定
4. ボタン、セレクトボックスのスタイル適用

**影響ファイル**:
- `app/page.tsx`
- `app/features/voicevox/*.tsx`（全コンポーネント）

---

### セッション3: レイアウト構造タスク
**責任範囲**: ページ全体のレイアウトとレスポンシブ対応
**作業内容**:
1. グリッドレイアウトの構築（左右2カラム）
2. レスポンシブデザインの実装（モバイル対応）
3. ヘッダー、フッターのスタイリング
4. スペーシングとパディングの調整

**影響ファイル**:
- `app/page.tsx`（レイアウト構造）
- 各セクションコンポーネント

---

### セッション4: 品質検証タスク
**責任範囲**: スタイル適用の検証とビルドチェック
**作業内容**:
1. 全画面でのスタイル適用確認
2. ダークモード対応の確認（あれば）
3. ビルドエラーの確認と修正
4. Tailwind purgeの動作確認

**検証項目**:
- ビルド成功（`npm run build`）
- スタイル適用の視覚確認
- レスポンシブ動作確認
- パフォーマンス確認

---

## 実行順序と依存関係
```
セッション1（基盤） → 並列実行可能 → セッション2（コンポーネント）
                                    → セッション3（レイアウト）
                  → 全タスク完了後 → セッション4（検証）
```

## 共通ガイドライン
- **FCIS+SMAC準拠**: スタイルはShell層で管理
- **Tailwindクラス優先**: インラインスタイルは避ける
- **セマンティック**: 意味のあるクラス名を使用
- **競合回避**: 各セッションは独立したファイルを編集

## デザイン指針
- **メインカラー**: ずんだ色（#8CC63F系）
- **背景**: 白またはライトグレー
- **アクセント**: 緑系グラデーション
- **フォント**: 日本語対応の読みやすいフォント

## チェックリスト
- [ ] Tailwind設定が正しく読み込まれている
- [ ] 全コンポーネントにスタイルが適用されている
- [ ] レスポンシブデザインが機能している
- [ ] ビルドエラーがない
- [ ] パフォーマンスに問題がない
